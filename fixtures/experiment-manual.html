Getting started

Configuring a project

Every project Halyard deploys is described by a single file at the root of your repository. This page walks through what goes in it, which values the CLI fills in for you, and what happens when the file and the dashboard disagree.

Creating the config file

Run the init command inside a repository that already has a package manifest. The CLI reads your lockfile, guesses the framework, and writes a halyard.config.json next to it. Nothing is uploaded at this point, so it is safe to run on a machine that has never been signed in.

If a config file already exists, init leaves it alone and prints a diff of the keys it would have changed. Pass the force flag when you want the guessed values to win. Commit the file: teammates who clone the repository get the same build without configuring anything in the dashboard.

!

The config file wins. When a key is set in both the file and the project settings page, the file is used and the dashboard shows the value greyed out. Delete the key from the file to hand control back to the dashboard.

Build and output

The build block tells Halyard how to turn your repository into something it can serve. Most frameworks need only the two commands below, and the CLI writes them for you during init. Everything else in the block has a default that works for a plain static site.

halyard deploy --project acme-storefront --env production --build "pnpm run build" --out dist --region eu-west-1 --wait

The output directory is resolved relative to the project root, never to the working directory the command ran from. A path that climbs above the root is rejected before the build starts, which is why a value like ../shared/dist fails immediately instead of halfway through an upload.

Limits and quotas

Each plan caps the size of a single deployment and the number of builds you can queue at once. The numbers below are per project, and they reset on the first day of your billing period rather than on a rolling window.

Setting Applies to Reset Limit
Deployment size Every plan Never 512 MB
Concurrent builds Team plan Immediate 8
Build minutes Team plan Monthly 6,000
Preview deployments Per branch Daily 120

Hitting a limit does not cancel a build that is already running. The queued work waits, and the CLI prints the position in the queue every ten seconds so a script can be left attached without flooding the log.
