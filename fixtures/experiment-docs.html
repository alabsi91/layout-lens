Configuration

Every Quill instance is created from a single options object. This page walks through the options you will reach for first, what they default to, and how they interact once the editor is running.

The options object

Pass the options as the second argument to the constructor. Anything you leave out falls back to the built-in default, so a working editor needs very little. The theme option is the one exception worth setting explicitly.

Options are read once

Quill reads the object when the editor is constructed. Changing a property later has no effect. To swap a theme at runtime, destroy the instance and build a new one with the content you kept.

javascript
1import Quill from "quill";
2
3const editor = new Quill("#editor", {
4 theme: "snow",
5 placeholder: "Write something…",
6 readOnly: false,
7 modules: { toolbar: "#toolbar" },
8});

Bounds and containers

Tooltips and pickers position themselves inside the element given by bounds. Set it to the scroll container when the editor lives inside a panel, otherwise a link tooltip near the edge can end up outside the visible area.

npm
CDN
bash
1# install the editor and its stylesheet
2npm install quill
3npm run dev

Option reference

Every option below is optional. The last column shows the version the option first shipped in.

Option Type Description Since
theme string Name of a registered theme. Falls back to the bare core theme. 1.0
placeholder string Shown while the editor is empty and not focused. 1.0
bounds Element Container that tooltips and pickers stay inside. 1.2
readOnly boolean Starts the editor in a non-editable state. 2.0

Wiring it up

  1. 1
    Add the container

    Give the editor a plain element with a fixed height. Quill will not create one for you.

  2. 2
    Load a theme stylesheet

    The snow and bubble themes each ship their own CSS file. Without it the toolbar renders as unstyled buttons.

  3. 3
    Construct the editor

    Build the instance after the container is in the document, so measurements are correct.

  4. 4
    Listen for changes

    Subscribe to text-change and store the delta, not the rendered HTML.
